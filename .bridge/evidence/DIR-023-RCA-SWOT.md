# DIR-023 — RCA: Dark-Mode Pastel Islands & Systematic Fix

**Status:** FIXED AND VERIFIED IN THE LIVE DOM
**Scope:** `src/styles/cuba-tokens.css` (central token layer) only. No component files edited.

---

## 1. Symptom

The dark shell rendered correctly, but inner surfaces still painted as bright
white/mint plates — the `/build-resume` step ribbon, action buttons, guide cards
and badges. Lead called these "Pastel Island Inversions".

---

## 2. Method (measurement, not inspection)

1. **Static census** — every colour-utility class actually present in `src/`,
   counted per class and per file. 3,149 matching lines; 214 neutral-family and
   195 coloured-family classes in scope.
2. **W3C contrast maths** — relative luminance computed with the spec formula
   against all three real dark surfaces (canvas `#0d0f16`, card `#15181f`,
   elevated `#1b1f29`). Values below are measured, never asserted.
3. **Built-bundle inspection** — confirmed the rules survive minification.
4. **Live Chromium DOM** — `getComputedStyle` on real elements, which is the
   only probe that cannot be fooled by an empty rule body.

---

## 3. Root causes

| # | Root cause | Evidence |
|---|---|---|
| **RC-1** | **Incomplete family coverage.** Only emerald, indigo and amber were mapped. blue, rose, purple, violet, sky, green, teal, cyan were untouched. | `bg-blue-50` 17.59:1, `bg-rose-50` 17.43:1, `bg-purple-50` 17.84:1 vs the `#0d0f16` canvas — near-white plates. These *are* the islands. |
| **RC-2** | **Unmapped dark INKS** — the inverse of the reported symptom and the more serious half. | `text-indigo-600` **2.62:1**, `text-indigo-950` **1.03:1**, `text-emerald-800` 2.14:1 on the elevated surface. Dark ink on a dark card is invisible. 25 of 29 pastel ink shades were below AA on at least one surface. |
| **RC-3** | **Unmapped opacity-modifier and variant forms.** `hover:bg-slate-50/80` compiles to a different class name than the bare utility, so a bare selector cannot see it. | `hover:bg-slate-50` ×175, `bg-indigo-50/50` ×24, `border-slate-200/80` ×118. A hover repainted the island *after* the resting state was fixed. |
| **RC-4** | **Unmapped line shades.** Only `border-{family}-200` was covered. | `border-slate-300` ×436, `border-slate-100` ×168, `border-indigo-300` ×44 — pale `#cbd5e1` hairlines on dark fills. |
| **RC-6** | **Unmapped Opacity-Modifier Classes.** Bare selectors (`.bg-emerald-50.bg-emerald-50`) bypass Tailwind's escaped-slash classes (`.bg-emerald-50\/70`, `.border-emerald-200\/90`, `.bg-white\/80`). | 591 total opacity classes in `src/`. `bg-emerald-50/70` rendered at 70% mint on `/build-resume` StepGuide until mapped to `rgba(52, 211, 153, 0.21)`. |

### RC-5 — the failure that hid all four (found only in the live DOM)

The first fix appeared correct in the source, in the built stylesheet, **and** in
every static check, yet the islands were still there.

**Cause:** the tints were emitted as `rgb(52, 211, 153 / 0.18)` — comma-separated
channels with slash alpha. That is **invalid CSS**. Chromium keeps the *selector*
and silently discards the *declaration*, producing a rule that matches with an
**empty body** (`rule.style.length === 0`). The rule looked present in the CSSOM
and did nothing at all.

**Proof:** an isolated matrix in the same browser — `rgb(52,211,153 / 0.18)` →
`decls=0`; `rgba(52,211,153,0.18)` → `decls=1`.

**Fix:** legacy comma-alpha `rgba()`. Rolldown now emits `#34d3992e`.

> This is exactly the class of defect DIR-023 exists to catch: *a fix that looks
> present and is absent from the DOM.*

---

## 4. The fix

Centralised in the existing token layer, inside `@layer components`, scoped to
`[data-theme='dark']` so **light mode is provably untouched**.

- **340 real classes** mapped across **11 coloured families** + the **neutral
  ramp** (slate / gray / zinc / neutral / stone), generated by scanning `src/` —
  no class was invented.
- Doubled-class selectors + `!important` to outrank Tailwind v4's precompiled
  `utilities` layer.
- `group-hover:` correctly emitted as a descendant rule (`.group:hover …`), not
  the invalid `:group-hover` pseudo.

## 5. SWOT

### Strengths
- **One central fix, 340 call sites repaired** — no component churn, and a component added tomorrow inherits the correction.
- **Durable by construction** — Tailwind emits `.bg-emerald-50{…var(--color-emerald-50)}` from one class name, so the mapping cannot drift per call site.
- **Light mode provably untouched** — every selector is dark-scoped; asserted in the shipped bundle.
- **Zero raw hex** for the neutral family — it reuses the existing Cuba surface/line/ink tokens.
- **Frozen baseline intact** — `git diff e314f715` over `src/cv-templates/` and `backend/services/aiRuntime.js` = **0 bytes**.

### Weaknesses
- **A build break mid-task.** An intermediate edit nested two `@layer components` blocks and broke `vite build` (`Unclosed block`). Caught by the build gate and repaired; it never reached `dist/`.
- **~600 generated selector lines.** Verbose, and it must be regenerated if the utility inventory changes.
- **Unmeasured pages.** Verified on the built shell and by exhaustive static census, **not** by crawling all 74 routes × 2 themes with a live identity — that crawler needs a running backend.
- **Decorative dividers stay at 1.33:1.** That is the pre-existing, Lead-approved `--cuba-dark-line` token; re-litigating it is a separate design decision.

### Opportunities
- **Promote RC-5 into a permanent CI guard.** A static regex rejecting `rgb(R, G, B / A)` would have caught a bug that defeated source review, the built bundle, and a passing static suite.
- **Extend the census to gradient stops and ring colours.** `ring-blue-500` (×131) and `ring-indigo-500` (×115) are not yet audited.
- **Convert `npm run audit:contrast` to run in CI** now that the residual classes are known.
- **Prune genuinely dead utility usage** instead of remapping it — several hundred of the 340 classes may be reachable from only one or two components.

### Threats
- **Silent-empty-rule regression.** Any future `rgb(… / …)` or minifier interaction could reintroduce RC-5 and every static check would stay green. The live-DOM probe is the only defence.
- **New components reintroducing raw pastels.** Mitigated by the central layer, but a component using an arbitrary value (`bg-[#ecfdf5]`) bypasses class-name mapping entirely.
- **Route-level regressions remain unmeasured.** Without the authenticated 74-route crawler, a page-specific composition could still composite a tint onto an unexpected surface.
- **Token-layer growth.** `cuba-tokens.css` is now large; continued growth increases the chance of another brace/layer accident of the kind caught above.
