# Candidate page-by-page UI/UX audit — 2026-10-14

## Method and limits

Weights: visual 15%, information architecture 15%, usability 20%, navigation 10%, functional completeness 15%, responsive 10%, accessibility 5%, data/integration 5%, design consistency 5%. When all dimensions have evidence, weighted score = Σ(score/10 × weight). **NR = not rated/unverified**, not zero and not a pass. A weighted page total is withheld if a dimension is NR. No global production-readiness rating is supportable.

Authenticated pages cannot be honestly scored from screenshots of a fixture or from source alone. Every original numbered entry is accounted for below, but most page-level runtime assessments remain unperformed. Template DOM/output checks are individual, not visual quality ratings. Source/guard/navigation dependencies are in [ROUTE_CENSUS.md](docs/candidate-audit/ROUTE_CENSUS.md). Additional shared routes are listed there and below; they are outside the old 93-entry numbering.

Only the isolated notification component received before/after browser interaction + viewport review. In order V/IA/U/N/F/R/A/D/C, provisional developer ratings are **6/7/4/NR/4/5/6/NR/7 → 7/7/8/NR/8/8/7/NR/8**. Reasons: existing heading/filter hierarchy adequate; stuck load/conflicting mutations/toast errors fixed; message clipping fixed; 8/8 widths and axe sample pass; no complete route guard, backend durability, screen-reader or zoom evidence. These are component-scoped judgements, not numerical release certification. Weighted total remains NR.

## Additional surfaces and state accounting

The 157-declaration census includes public authentication, marketing/content, job discovery, cover aliases, legacy mounts and other-role boundaries. It is deliberately not called 157 candidate pages. For each non-numbered declaration, all nine ratings and runtime status are **NR** until executed. Query/modal states are not included in that count: profile sub-sections, Account/TOTP, import/sync/template/preview dialogs, job apply/detail, support create/reply, CBT/live session states, checkout and reset/verification/OAuth flows require separate state captures.

Shared-shell assessment is **unverified**: the notification lab intentionally does not render CubaCandidateShell. This prevents assigning a shell's score to every route. Baseline inventory corrections and per-route exact source dependencies are documented separately.

## Template caveats

All four fixtures test DOM presence/no crash; only normal creates/parses PDF and generates CV DOCX. DOM Unicode presence is not glyph rendering. Cv1 screenshot reviewed manually shows missing Telugu glyphs; restricted runtime blocks remote fonts and lacks some system script fonts. Other 54 screenshots were generated, not independently visually approved. A concurrent run failed Cover4's error boundary (216/220); final isolated run passed 220/220 after test-cache isolation and added diagnostics. Retain that uncertainty.
