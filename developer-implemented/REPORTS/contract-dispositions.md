## Additional source tracing at implementation baseline

The table above is historical triage; this section gives current dispositions. All claims of a working UI are unverified until browser/DB tests run. Authorization is not relaxed.

1. **Employer verification**: `AdminModerationTab.tsx` sends POST `/admin/employer-applications/{id}/verify` and swallows failures while operating on fabricated records. Actual `PATCH /api/admin/employer-applications/:uid` (`backend/index.js`) requires `status` = approved/rejected/active, optional `expectedStatus` and `reason`; authenticated admin write policy includes `users.update` and `system.config.write`; response `{success,status,employer}`. UID is identity UID, not a synthetic fixture ID. **NOT IMPLEMENTED**: load real records, preserve guards, handle identity and persistence failures; no safe mechanical substitution.
2. **Job moderation**: same UI POST `/admin/jobs/{id}/moderate` sends `isSpam` plus `flagged` status. Actual `PATCH /api/admin/jobs/:jobId` accepts exactly one `status` (active/pending/inactive/archived) or `isFeatured`, optional `expectedStatus`/`expectedFeatured`, with admin write authorization; response `{success,status,isFeatured,revision}`. `flagged` and `isSpam` have no equivalent operation. **NOT IMPLEMENTED**, with service concurrency and mapping hypothesis in `NEW-FINDINGS.md`; do not claim spam flag parity.
3. **Queue GET**: old fallback `/admin/queues` replaced with authenticated `GET /api/platform/queues` (`security.read`); returns sampled `{summary,jobs}`. Parser tested; **IMPLEMENTED — NOT VERIFIED** browser and MariaDB.
4. **Dead-letter retry**: old `/admin/queues/dead-letter-queue/retry` replaced with `POST /api/platform/queues/retry` for one notification job `{queue:'notification',jobId}`; platform auth and recent-admin requirement remain. Success `{success:true,retriedCount:1,jobId}` checked; no delivery claim. **IMPLEMENTED — NOT VERIFIED**.
5. **Queue-wide retry**: `/admin/queues/{X}/retry` unsupported; actual retry requires a single notification job ID, not a queue name. Unsupported bulk controls removed; **IMPLEMENTED — NOT VERIFIED**, not equivalent bulk functionality.
6. **User status**: old `POST /admin/users/:id/status` swallows errors and mutates fixture state. `PATCH /api/admin/users/:uid` (`backend/routes/adminUsers.js`) accepts `suspended` and optional `expectedSuspended`, requires users.update plus admin write gate; returns `{success,user}` with `user.suspended`. Fixture records and many other false actions remain; **NOT IMPLEMENTED**, do not blindly use fabricated IDs or optimistic success.
7. **Coupon**: `POST /api/coupons/validate` accepts `{code}`, returns `{success,valid,coupon:{code,discount}}`; public route uses optional auth and validates server-side. Strict parser replaces hardcoded fallback; **IMPLEMENTED — NOT VERIFIED** real DB/browser. Order creation revalidates the coupon.
8. **Blog list/create**: public list now `GET /api/blog-data?publishedOnly=true`; parser requires explicit published rows, errors shown. Admin list has its own `GET /api/admin/blog/posts`, paginated/admin read; editor create has `POST /api/blog-data/:id` requiring editorial write permission, not `POST /blog/posts`. Its payload must provide `published`, not merely `status:'published'`, and MySQL upsert lacks a CAS guard. Public-list correction **IMPLEMENTED — NOT VERIFIED**; admin list/editor creation **NOT IMPLEMENTED**, do not silently retarget an unsafe write.
9. **Blog item edit/delete**: `GET /api/blog-data/:id` returns `{success,post}`, `POST /api/blog-data/:id` saves without revision CAS, and `DELETE /api/blog-data/:id` requires current `expectedRevision` and editorial write permission. Existing client expects a bare post, PUTs a wrong path, or deletes without revision and swallows errors. **NOT IMPLEMENTED**. Additional public slug/list security fix M9-P01 is separately recorded.
10. **Jobs**: `GET /api/jobs-data` is public and enforces active/unexpired status in the route and repository, returning `{success,jobs}` with relational snake-case fields. Source repository ignores q/location/type; UI now maps fields and filters returned rows locally, removes invented statistics. **IMPLEMENTED — NOT VERIFIED** live DB/browser; local unit parser/filter tests pass.
11. **Platform status**: `GET /api/admin/platform/status?tenantId=...` requires `system.config.read` and recent admin auth, responds `{success,hasDedicatedBYOK,credentialCount,providers}`; tenant user may not hold those privileges. Caller now uses this path, does not send tenant headers to legacy routes, treats unavailable/forbidden/malformed data as unavailable without preventing independent tenant configuration loading or asserting gateway health. **IMPLEMENTED — NOT VERIFIED** live auth/browser; parser unit test passes.
