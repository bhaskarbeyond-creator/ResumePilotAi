# Storage Architecture — GAP-11

**Status:** 🟡 PARTIAL (no certified object-storage provider; no provider credentials; not required for current flows)

## Current file/asset capabilities

| Capability | Current implementation | Server-side object storage? |
|---|---|---|
| Resume/CV PDF export | Generated by the `/api/export` Pipeto browser or returned as a file | No — generated transiently, no persistence |
| DOCX export | Generated by `services/docxExport.js` | No — generated on demand |
| Cover letter export | Same render pipeline | No — generated on demand |
| Resume import (PDF/DOCX/text) | Parsed client-side; no raw file retained server-side | No |
| Avatar upload | Verified via `POST` profile API; normalized dimensions; stored in application data (MariaDB) or Firebase photoURL | No provider abstraction |
| Portfolio assets | Inline/base64 or URL-controlled content; no server-owned upload | No |

## Why an S3/R2 provider is not a current correctness dependency

1. The generated PDF/DOCX artifacts are **not persisted** server-side; the backend streams/returns them after an authorized repository read.
2. The Admin Storage Settings screen intentionally refuses to enable a storage provider because there is **no certified** server-owned signed-upload adapter, malware scan, lifecycle retention, or tenant-isolation proof.
3. Avatar and profile data remain in the **MariaDB application datastore** (authoritative) or Firebase **identity** photo URL (identity only).
4. The enterprise tenancy storage pathing helpers (`backend/enterprise/tenantStorage.js`) exist but only cover object-key ownership parsing for future certified storage. The certification test `enterprise-architecture.test.js` explicitly requires `backend/enterprise/storageProvider.js` to remain **removed**, so a provider must be added outside the restricted enterprise data-plane path.

## What would be required to close this as COMPLETE

- Vendor-neutral provider abstraction for local dev + S3/R2, with server-owned signed upload/download URLs.
- Ownership/tenant isolation checks on every object.
- Content-type, size, and malware controls.
- Retention, deletion, encryption, restore/backup evidence.
- Secret-manager credentials or workload identity in production (currently not present).
- Browser, failure-path, and production tests.

## Owner / dependency / plan

- **Owner:** cloud/SRE + application engineer.
- **Dependency:** provider credentials (Hostinger/R2/S3), secret manager, signed-URL certification.
- **Plan:** add a storage provider outside `backend/enterprise` (so the existing zero-provider contract stays valid), wire the export/avatar flows only after the provider is certified, then update this document and the GAP matrix.

## Exact blocker / operational note

No production object-storage credentials are present in `.env.example` or the Hostinger configuration. Until a certified provider is configured, administrative storage activation must remain **disabled** (fail-closed), as the current Storage Settings screen does.
