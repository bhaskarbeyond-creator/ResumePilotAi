# Production architecture security review

This is an architecture-gap review, not a deployment certification. Local code controls cannot prove cloud IAM, provider configuration, network topology, alert delivery, backups, or operational response.

| Area | Implemented in code | Production dependency / residual risk | Required evidence |
|---|---|---|---|
| Secret management | Browser AI/payment secrets removed; split public/server-only settings; tracked-secret tests; local secret files use mode `0600`; ADC adapter supported. | Environment variables and local SMTP/Firebase fallback files are process-level secrets. Secret-manager injection, rotation, access logging, and filesystem ownership are deployment concerns. Historical credentials require rotation. | Secret-manager policy, IAM bindings, rotation records, filesystem permissions, secret-access logs. |
| Firebase Admin / Workload Identity | Firebase Admin v14 adapter supports Application Default Credentials and avoids auto-loading repository JSON keys. | ADC is only secure if the runtime service account and metadata access are correctly scoped. The admin SDK bypasses Firestore rules by design. | Workload Identity configuration, least-privilege IAM, service-account inventory, denied-permission tests. |
| Firestore / Realtime Database | Deny-by-default rules; owner/RBAC constraints; server-only billing/token/secret state; adversarial Emulator suites. | Emulator suites are not locally executed because Java is unavailable. Existing production documents and queries may not conform to new owner/status fields and indexes. | Java-enabled Emulator run, staging deployment, index/query tests, rules deployment audit. |
| Proxy topology / client IP | Exact CORS allowlist; PHP proxy overwrites forwarded IP; backend trusts loopback by default; same-origin frontend API. | A cloud load balancer may add a different number of trusted hops. A wrong `TRUST_PROXY_HOPS` can collapse rate limits or permit spoofing. | Network diagram, direct-origin firewall proof, spoofed-XFF tests through every proxy hop, effective client-IP logs. |
| CSP and static headers | Apache CSP/HSTS/frame/referrer/permissions headers; inline bootstrap removed; static regression test. | Headers apply only when the checked-in Apache configuration is actually used. Third-party payment/auth scripts may require report-only tuning. | Headers captured from every production hostname/path, CSP report-only telemetry, end-to-end payment/auth browser test. |
| SMTP / IMAP | Public-network classification, DNS-result pinning, TLS/SNI/certificate validation, encrypted transport requirement, recipient checks. | SMTP circuit breaker and logs are process-local. No provider bounce/complaint webhook, suppression list, or shared outbox is implemented. | Real CA-valid connectivity tests, credential rotation, failover exercise, bounce/complaint handling and suppression evidence. |
| Rate limiting | Global IP and per-account AI/email/export/contact/scraper/messaging limits; Firestore daily AI quota. | Short-window buckets are in process memory, so limits multiply across instances and reset on restart. | Shared Redis/gateway limiter, multi-instance load test, bypass test across replicas and IPv4/IPv6/proxies. |
| AI cost controls | Authenticated backend-only requests, body limits, server keys, account burst limits, durable daily quota. | Provider billing limits, per-model token budgets, alerting, and emergency shutoff are external. Quota transaction availability depends on Firestore. | Provider budget caps, billing alerts, forced-quota test, outage/fail-closed test, cost dashboard. |
| Payment creation / entitlement | Server catalog, owner-bound orders, idempotency, provider validation helpers, transactional activation, Stripe replay ledger, server coupon validation. | Only Stripe has a webhook reversal path. PayPal/Razorpay/Paytm/PhonePe rely on status APIs/client completion; exact provider schemas remain sandbox-unvalidated. Short-lived coupon reservations require TTL/cleanup operations. | Provider sandbox runs, signed webhook/callback tests, reconciliation jobs, coupon reservation cleanup/TTL, accounting comparison. |
| Recurring billing | UI preference/cancellation requests are server-owned; later purchases extend existing paid time. | Current payment code primarily creates one-time orders/intents, not fully modeled provider subscriptions. `autoRenew` does not prove a provider recurring agreement. | Product decision and provider subscription implementation or removal of recurring claims; renewal/cancel webhook evidence. |
| Logging / monitoring | Request IDs, structured API errors, payment/security audit documents, no raw OAuth tokens in normal logs. | Most runtime logging uses `console`; no centralized immutable sink, retention policy, PII redaction verification, alert rules, or SLO monitoring is supplied. | Log pipeline, access controls/retention, redaction tests, SIEM alerts, webhook/AI/auth anomaly dashboards, on-call runbooks. |
| Error handling | Generic auth/reset/provider errors, request IDs, no provider secret echo, global API error handler. | Background email work can fail after HTTP acceptance; no durable outbox/retry proof. Provider timeout ambiguity needs reconciliation. | Failure injection, dead-letter/outbox evidence, reconciliation runbook, user-support status behavior. |
| PDF renderer | Fixed application destination, ownership/entitlement check, request limits, HTML sanitization, browser network egress interception, and Firestore-backed hashed one-time render tokens that work across replicas. | Chromium uses `--no-sandbox`; in-process concurrency is per replica. A browser exploit would share the backend container. | Dedicated non-root sandboxed render worker/container, seccomp/AppArmor, egress firewall, distributed concurrency quotas, token TTL cleanup, malicious-document test. |
| DOCX renderer | Owner-scoped, entitlement-checked generation now produces a valid WordprocessingML package with Summary, Experience, Education, Skills, Languages, Projects, Certifications, and custom sections. | DOCX is semantic rather than a pixel-perfect reproduction of all 51 visual PDF templates. | Validate Word/LibreOffice interoperability and decide whether template-specific Word layouts are a separate product requirement. |
| Backup / recovery | Destructive browser-side merge/restore paths disabled; account deletion is server-authoritative and recursive for known collections. | No verified encrypted backup, point-in-time recovery, restore drill, RPO/RTO, or complete cross-store deletion inventory is present. Realtime messaging deletion requires an operational data lifecycle. | Backup policy, encryption keys, restore drill, RPO/RTO sign-off, GDPR deletion inventory for Firestore/RTDB/logs/backups/providers. |
| Deployment / CI | Firebase deployment config, clean dependency audits, security/CodeQL workflow templates, Dependabot config. | Workflow templates are not active because GitHub workflow permission was unavailable. No IaC proves headers, IAM, network, secret manager, or runtime flags. | Installed green workflows, required checks, staging/prod IaC review, immutable artifact/provenance, deployment approvals and rollback exercise. |

## Multi-instance blockers

Before horizontal production scaling, move process-local rate buckets, SMTP circuit state, export concurrency, and any background work coordination to shared infrastructure. Add payment/provider reconciliation workers and ensure all transient records have managed TTL/cleanup. Verify that a request can move between instances without losing OAuth, password reset, entitlement, or webhook idempotency state.

OAuth state/exchange records, password reset state, payment orders, webhook event IDs, and daily AI quotas are already in Firestore and therefore survive instance changes. This does not replace load, race, and regional-consistency testing.
